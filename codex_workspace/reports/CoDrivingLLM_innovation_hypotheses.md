# CoDrivingLLM 创新点假设表

> 方法来源：借鉴 `hypothesis-generation` 的“观察 → 研究问题 → 假设 → 机制 → 实验 → 指标 → 判别标准”结构  
> 使用目的：把候选创新点转成可验证实验，避免“凭感觉加模块”  
> 注意：以下均为候选假设，不是已验证结论；最终是否成立以实验结果为准

## 0. 研究问题

**核心问题：**

> 在 LLM 驱动的多车协同驾驶中，能否通过安全约束、事件触发、自适应记忆和协商机制，提高系统在成功率、安全性、效率和成本上的综合表现？

# 2. 具体假设与实验设计

## H1：安全过滤层假设

### 2.1 观察与动机
现有系统中，LLM 输出虽然经过 prompt 中的规则提示，但缺少独立、可审计的“动作级安全过滤器”。  
LLM 可能给出语义上合理但物理上危险的动作，例如在冲突车辆较近时仍选择加速。

### 2.2 研究问题
> 在 LLM 决策后加入基于安全约束的过滤层，能否降低碰撞率，同时不明显牺牲通行效率？

### 2.3 假设
**H1：**  
在 CoDrivingLLM 的 LLM 动作输出后加入安全过滤器，可以显著降低碰撞率，并保持成功率不低于原始 0-shot baseline 的 95%。

### 2.4 机制解释
1. LLM 负责高层语义推理；
2. 安全过滤器负责物理可行性校验；
3. 当 TTC、车头时距或冲突风险超过阈值时，强制降级为减速 / 让行 / 保持；
4. 通过“语义决策 + 物理约束”的混合架构降低危险动作发生概率。

### 2.5 实验设计

| 组别 | 方法 | 目的 |
|---|---|---|
| A | 0-shot | 原始 baseline |
| B | 0-shot + 安全过滤 | 验证安全层 |
| C | no-negotiation + 安全过滤 | 验证安全层是否独立于协商有效 |
| D | 2-shot + 安全过滤 | 验证安全层与记忆是否互补 |

### 2.6 核心指标

| 指标 | 目标方向 |
|---|---|
| 碰撞率 | 下降 |
| 成功率 | 不低于 baseline 的 95% |
| 超时率 | 不显著上升 |
| 平均速度 | 不显著下降 |
| 安全覆盖次数 | 可解释，不爆炸式增长 |
| LLM 调用次数 | 不上升 |

### 2.7 判别标准
- **支持 H1：**
  - 碰撞率下降 ≥ 20%；
  - 成功率下降 ≤ 5%；
  - 超时率上升 ≤ 10%；
  - 安全覆盖次数占总动作数的比例在可接受范围内。
- **不支持 H1：**
  - 碰撞率下降不明显；
  - 或成功率下降 > 10%；
  - 或系统变得过度保守，超时率大幅上升。

### 2.8 风险与替代方案
- 风险 1：过滤器过保守，导致超时增加；
- 风险 2：安全规则与仿真动作空间不匹配；
- 替代方案：将硬过滤改为软约束，在 prompt 中注入风险等级，再由 LLM 选择动作。

### 2.9 代码落点
- 新增 `safety_filter.py`
- 修改 `llm_agent_action.py` 输出后处理
- 在 `Run_multi_CAV_LLM.py` 中增加 `--safety-filter` 开关

## H2：事件触发 LLM 决策假设

### 2.1 观察与动机
当前系统每一步都调用 LLM，导致：
- token 成本高；
- 延迟高；
- 决策频率可能超过必要水平。

### 2.2 研究问题
> 如果只在风险变化或冲突出现时调用 LLM，能否在保持成功率的同时显著降低调用次数？

### 2.3 假设
**H2：**  
采用事件触发机制后，LLM 调用次数可下降至少 30%，而成功率下降不超过 5%。

### 2.4 机制解释
1. 每步先计算风险指标；
2. 若风险低且变化小，则复用上一动作或使用保守规则；
3. 若出现以下事件，则调用 LLM：
   - 冲突车辆出现；
   - TTC 低于阈值；
   - 速度差变化超过阈值；
   - 目标车辆接近冲突点；
   - 协商结果改变。

### 2.5 实验设计

| 组别 | 方法 | 目的 |
|---|---|---|
| A | 0-shot，每步调用 | baseline |
| B | 事件触发 | 主实验 |
| C | 事件触发 + 安全过滤 | 组合效应 |
| D | 固定间隔调用 | 排除“只是降低频率”的简单解释 |

### 2.6 核心指标

| 指标 | 目标方向 |
|---|---|
| LLM 调用次数 | 下降 ≥ 30% |
| token 消耗 | 下降 ≥ 30% |
| 成功率 | 下降 ≤ 5% |
| 碰撞率 | 不上升 |
| 平均延迟 | 下降 |
| 决策间隔 | 可解释 |
| 事件触发率 | 可解释 |

### 2.7 判别标准
- **支持 H2：**
  - 调用次数下降 ≥ 30%；
  - 成功率下降 ≤ 5%；
  - 碰撞率不上升；
  - 延迟明显下降。
- **不支持 H2：**
  - 调用次数下降但成功率下降 > 10%；
  - 或事件触发过于频繁，未能显著降低成本。

### 2.8 风险与替代方案
- 风险 1：事件触发过少，错过关键决策时机；
- 风险 2：阈值难以调节；
- 替代方案：使用自适应阈值，根据风险等级动态调整触发灵敏度。

### 2.9 代码落点
- 新增 `event_trigger.py`
- 在主循环中增加 `--event-trigger`
- 记录每步是否触发、风险值、动作来源

## H3：自适应记忆与遗忘假设

### 2.1 观察与动机
现有记忆策略主要是固定 few-shot，如 2-shot / 5-shot。  
但不同场景对经验的需求不同，固定数量可能导致：
- 低风险时引入无关记忆；
- 高风险时经验不足；
- 过时记忆干扰决策。

### 2.2 研究问题
> 与固定 2-shot / 5-shot 相比，自适应记忆检索是否能提高成功率并降低无效记忆干扰？

### 2.3 假设
**H3：**  
基于场景相似度、时间衰减和成功率的自适应记忆检索，成功率高于固定 2-shot / 5-shot，且不增加 LLM 调用次数。

### 2.4 机制解释
1. 对当前场景构建检索向量；
2. 计算候选记忆的：
   - 场景相似度；
   - 时间新近度；
   - 成功 / 失败标签；
   - 动作一致性；
3. 动态选择 top-k，而不是固定 k=2 或 k=5；
4. 对低质量记忆降权或遗忘。

### 2.5 实验设计

| 组别 | 方法 | 目的 |
|---|---|---|
| A | 0-shot | 无记忆 baseline |
| B | 2-shot | 固定记忆 |
| C | 5-shot | 固定记忆 |
| D | 自适应 top-k | 主实验 |
| E | 自适应 + 遗忘 | 验证遗忘作用 |
| F | 只用成功记忆 | 排除失败记忆干扰 |
| G | 成功 + 失败记忆 | 验证失败经验价值 |

### 2.6 核心指标

| 指标 | 目标方向 |
|---|---|
| 成功率 | 高于 2-shot / 5-shot |
| 碰撞率 | 下降 |
| 超时率 | 不上升 |
| 平均检索条数 | 可控 |
| 记忆命中率 | 提高 |
| 无效记忆引用率 | 下降 |
| LLM 调用次数 | 不上升 |

### 2.7 判别标准
- **支持 H3：**
  - 成功率高于固定 2-shot / 5-shot 至少 3 个百分点；
  - 碰撞率不上升；
  - 平均检索条数不超过 5；
  - 无效记忆引用率下降。
- **不支持 H3：**
  - 成功率无提升；
  - 或检索成本上升明显；
  - 或过时记忆干扰更强。

### 2.8 风险与替代方案
- 风险 1：记忆库样本量不足，导致自适应检索不稳定；
- 风险 2：失败记忆可能引入误导；
- 替代方案：先做“成功记忆 + 相似度过滤”，再逐步引入失败记忆。

### 2.9 代码落点
- 修改 `memory.py`
- 在 `llm_agent_action.py` 中替换固定 few-shot 逻辑
- 增加记忆版本号与快照记录

## H4：机制设计式协商假设

### 2.1 观察与动机
当前协商模块主要基于冲突严重程度生成建议。  
如果将协商抽象为冲突图上的资源分配问题，可以引入更严格的机制设计视角。

### 2.2 研究问题
> 使用冲突图 + 机制设计规则，能否比原始 LLM 协商更稳定地提升通行效率和公平性？

### 2.3 假设
**H4：**  
基于冲突图和优先级机制的协商方法，在成功率、碰撞率和公平性指标上优于原始 LLM 协商。

### 2.4 机制解释
1. 将车辆之间的冲突关系建模为图；
2. 节点表示 CAV；
3. 边表示潜在冲突；
4. 根据以下因素计算优先级：
   - 到冲突点距离；
   - 当前速度；
   - 道路优先权；
   - 协商历史；
   - 安全裕度；
5. 使用类似投票、拍卖或加权优先级的机制决定通行顺序；
6. LLM 负责解释、软约束补充和异常处理。

### 2.5 实验设计

| 组别 | 方法 | 目的 |
|---|---|---|
| A | no-negotiation | 无协商 |
| B | 原始 CoDrivingLLM 协商 | baseline |
| C | 冲突图 + 距离优先级 | 简单机制 |
| D | 冲突图 + 加权优先级 | 主实验 |
| E | 冲突图 + 投票 / 拍卖机制 | 进阶机制 |

### 2.6 核心指标

| 指标 | 目标方向 |
|---|---|
| 成功率 | 提高 |
| 碰撞率 | 下降 |
| 平均等待时间 | 下降 |
| 公平性指标 | 改善 |
| 协商消息长度 | 可控 |
| 协商延迟 | 可控 |
| 冲突消解成功率 | 提高 |

### 2.7 判别标准
- **支持 H4：**
  - 成功率高于原始协商；
  - 碰撞率下降；
  - 平均等待时间下降；
  - 车辆间通行次数分布更均衡。
- **不支持 H4：**
  - 成功率无提升；
  - 或协商延迟显著上升；
  - 或机制规则过度复杂但收益不明显。

### 2.8 风险与替代方案
- 风险 1：机制设计实现复杂，调试成本高；
- 风险 2：某些场景中规则优先级可能不如 LLM 灵活；
- 替代方案：先实现“冲突图 + 距离优先级”，再逐步扩展到更复杂机制。

### 2.9 代码落点
- 新增 `conflict_graph.py`
- 修改 `llm_agent_negotiation_system.py`
- 增加协商记录与公平性统计

## H5：不确定性感知决策假设

### 2.1 观察与动机
LLM 在陌生或复杂场景中可能给出过度自信但错误的决策。  
如果能估计不确定性，就可以在高不确定性时采取保守策略。

### 2.2 研究问题
> 引入不确定性估计是否能在分布外场景中降低碰撞率，并提升系统鲁棒性？

### 2.3 假设
**H5：**  
当 LLM 输出不确定性或环境预测不确定性较高时，系统应更多触发保守动作，从而在分布外场景中降低碰撞率。

### 2.4 机制解释
1. 从 LLM 输出中估计置信度；
2. 从轨迹预测或冲突预测中估计环境不确定性；
3. 当不确定性超过阈值时：
   - 降低速度；
   - 增加让行概率；
   - 触发安全过滤；
   - 或请求额外协商。

### 2.5 实验设计

| 组别 | 方法 | 目的 |
|---|---|---|
| A | 0-shot | baseline |
| B | 0-shot + 不确定性感知 | 主实验 |
| C | 0-shot + 随机保守动作 | 排除“只是更保守”的解释 |
| D | 0-shot + 安全过滤 | 对比不同保守机制 |

### 2.6 核心指标

| 指标 | 目标方向 |
|---|---|
| 碰撞率 | 下降 |
| 成功率 | 不明显下降 |
| 高不确定性场景成功率 | 提高 |
| 保守动作触发率 | 与不确定性相关 |
| 校准误差 | 下降 |
| 平均速度 | 不过度下降 |

### 2.7 判别标准
- **支持 H5：**
  - 高不确定性子集上的碰撞率下降；
  - 保守动作触发与实际风险相关；
  - 整体成功率下降 ≤ 10%。
- **不支持 H5：**
  - 不确定性估计与实际风险无相关；
  - 或只是通过过度保守降低碰撞，但成功率大幅下降。

### 2.8 风险与替代方案
- 风险 1：LLM 自报置信度不可靠；
- 风险 2：不确定性估计复杂；
- 替代方案：使用多候选动作一致性或轨迹预测方差作为代理不确定性。

### 2.9 代码落点
- 新增 `uncertainty.py`
- 修改决策与安全过滤逻辑
- 记录不确定性值、触发动作和结果

# 4. 论文写作角度

即使实现动作较小，也可以从以下角度扩展论文内容：

1. **系统架构角度**  
   讨论“LLM 高层决策 + 规则安全约束 + 事件触发 + 记忆增强”的混合智能体架构。

2. **控制论角度**  
   将安全过滤器解释为安全屏障或动作级约束控制器。

3. **认知科学角度**  
   将自适应记忆解释为经验学习、遗忘曲线和案例推理。

4. **交通工程角度**  
   讨论冲突消解、通行效率、公平性和多车协同。

5. **系统效率角度**  
   强调 LLM 调用成本、延迟和事件触发机制。

6. **统计评估角度**  
   引入多 seed、置信区间、显著性检验和消融分析。

7. **人机交互角度**  
   讨论 LLM 输出的可解释性与人类可理解性。

8. **安全关键系统角度**  
   讨论 LLM 在自动驾驶决策中的适用边界与失败模式。

# 5. 优先级建议

## 第一优先级
**H1 安全过滤层 + H2 事件触发**  
理由：
- 实现难度低；
- 收益容易量化；
- 论文叙事清晰；
- 实验风险小；
- 与现有系统兼容性好。

## 第二优先级
**H3 自适应记忆**  
理由：
- 与现有 memory.py 契合度高；
- 容易做丰富消融；
- 有认知科学与经验学习叙事；
- 但效果需要实验验证。

## 第三优先级
**H4 机制设计协商**  
理由：
- 理论贡献强；
- 论文写作空间大；
- 但实现和调试成本较高，适合作为第二阶段创新。

## 观察项
**H5 不确定性感知**  
理由：
- 理论价值高；
- 但实现复杂，且不确定性估计是否可靠需要先验证。

# 6. 结论

最适合你当前阶段的创新组合是：

> **安全过滤 + 事件触发 + 自适应记忆**

它可以形成一个完整的研究故事：

```text
低风险 → 少调用 LLM → 复用经验
高风险 → 调用 LLM → 生成候选动作
输出后 → 安全过滤 → 执行安全动作
```

这套设计：
- 实现难度适中；
- 每个模块都有明确假设；
- 每个模块都有可量化指标；
- 论文可以覆盖安全、效率、记忆、协同驾驶和跨学科解释；
- 相比单纯“加一个 prompt”，更容易形成系统性贡献。
