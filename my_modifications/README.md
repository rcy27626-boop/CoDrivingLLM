# my_modifications

本目录用于管理本人在复现 CoDrivingLLM 论文过程中**对原项目代码的修改与新建文件**。

## 📁 目录结构

```
my_modifications/
├── README.md              # 本说明文件
├── new_files/             # 📝 新建的文件
│                          #   存放复现过程中全新创建的文件（如实验脚本、工具类等）
│                          #   每个文件应附同名 .md 说明：用途、依赖、运行方式
│
└── change_logs/           # 📋 对原项目文件的修改说明
                           #   不存放修改后的代码（代码直接在原文件上改）
                           #   只记录：修改时间、原文件路径、修改原因、具体 diff、影响范围
```

## 📐 使用规范

### 1️⃣ 新建文件 → `new_files/`
- 文件直接放进 `new_files/`，**保持可独立运行**
- 同一文件名下创建同名 `.md` 说明文档，例如：
  - `new_files/eval_metrics.py`
  - `new_files/eval_metrics.md`  ← 说明用途、调用方式、输入输出

### 2️⃣ 修改原项目文件 → `change_logs/`
- **代码本身直接在原文件上修改**（便于在原项目上跑实验）
- 在 `change_logs/` 下对应记录一条修改说明，建议命名：
  ```
  YYYYMMDD_<原文件名>_<简短描述>.md
  例如：20260728_Run_multi_CAV_LLM_增加batch模式.md
  ```

每条修改说明至少包含：
| 字段 | 说明 |
|------|------|
| 📅 修改时间 | 精确到日期 |
| 📂 原文件路径 | 相对项目根目录 |
| 🎯 修改目的 | 为什么改 |
| 🔧 具体改动 | diff 或代码片段 |
| ⚠️ 影响范围 | 是否影响其他文件、实验复现性 |

## 🔄 与 Linux 服务器同步建议

由于本机改代码、服务器跑实验，**修改前请先确认服务器端的代码版本**：

```bash
# 服务器端
cd CoDrivingLLM
git pull   # 同步本机推送的修改
```

建议每次本地修改后立即 `git push`，服务器再 `git pull` 后跑实验，避免版本漂移。

## 📌 备注

- 本目录**不替代原项目代码**，仅作为复现工作的"工作日志 + 新增代码收纳"
- 修改原文件前建议先 `git commit` 当前状态，便于回溯
