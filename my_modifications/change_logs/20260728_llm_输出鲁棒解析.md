## 🎯 修改目的

冒烟测试中观察到，硅基流动的 **Qwen2.5-7B-Instruct** 输出的决策格式与 gpt-4o-mini 不完全一致：
- 多数时候能正常返回 `Final Answer: { "decision": {"FASTER"} }`
- 但偶尔返回奇怪的格式（如 `LAN current"**_idle**:`），导致 `extract_decision` 解析失败 → `None` → `get_action_id_from_name` 返回 `-1` → `KeyError: -1` 程序崩溃

原代码的解析逻辑**单一路径 + 无 fallback**，遇到格式异常就直接挂掉。

## 🔧 具体改动

### 改动 1：[llm_agent_action.py:94-110](llm_controller/llm_agent_action.py#L94-L110) `get_action_id_from_name` 加 fallback

**原代码：**
```python
def get_action_id_from_name(self, action_name, actions_all):
    ...
    for id, name in actions_all.items():
        if name == action_name or name == action_name.upper():
            return id
    return -1  # 找不到时返回 -1，会导致 KeyError
```

**改成：**
```python
def get_action_id_from_name(self, action_name, actions_all):
    ...
    for id, name in actions_all.items():
        if name == action_name or name == action_name.upper():
            return id
    # Fallback: 返回 IDLE 的 id（最安全动作，避免 KeyError 崩溃）
    return 1
```

### 改动 2：[llm_agent_action.py:205-232](llm_controller/llm_agent_action.py#L205-L232) `extract_decision` 重写为鲁棒解析

**原代码：单一路径，解析失败 return None**

```python
def extract_decision(self, response_content):
    try:
        start = response_content.find('"decision": {') + len('"decision": {')
        end = response_content.find('}', start)
        decision = response_content[start:end].strip('"')
        if self.is_intersection:
            if "FASTER" in decision: ...
            elif "SLOWER" in decision: ...

        ...

    except Exception as e:
        print(...)
        return None
```

**改成：三策略 + fallback 到 IDLE**
```python
def extract_decision(self, response_content):
    """鲁棒地从 LLM 输出中提取决策 action。
    解析失败时 fallback 到 IDLE（最安全动作），避免程序崩溃。
    """
    try:
        decision = None
        # 策略 1: 标准格式 "decision": {"FASTER"}
        if '"decision"' in response_content:
            start = response_content.find('"decision"')
            brace_start = response_content.find('{', start)
            if brace_start != -1:
                brace_end = response_content.find('}', brace_start)
                if brace_end != -1:
                    decision = response_content[brace_start + 1:brace_end].strip().strip('"').strip("'")

        # 策略 2: 全文搜 action 关键字（兼容 Qwen 等模型格式不稳定）
        if not decision or not any(a in decision.upper() for a in ['FASTER', 'SLOWER', 'LANE_LEFT', 'LANE_RIGHT', 'IDLE']):
            upper = response_content.upper()
            for action in ['FASTER', 'SLOWER', 'LANE_LEFT', 'LANE_RIGHT', 'IDLE']:
                if action in upper:
                    decision = action
                    break

        # 策略 3: 标准化到合法 action
        if self.is_intersection:
            if decision and "FASTER" in decision.upper(): return "FASTER"
            elif decision and "SLOWER" in decision.upper(): return "SLOWER"
            elif decision and "IDLE" in decision.upper(): return "IDLE"
        else:
            if decision and "LANE_LEFT" in decision.upper(): return "LANE_LEFT"
            ...
        # 全部失败：fallback 到 IDLE
        print(f"无法解析 LLM 输出: {response_content[:100]!r}，fallback 到 IDLE")
        return "IDLE"
    except Exception as e:
        print(f"Error in extracting decision: {e}，fallback 到 IDLE")
        return "IDLE"
```

## 📚 经验总结

📌 **LLM 应用的常见坑**：
- 不同模型对同一 prompt 的响应格式不同
- "软"规定的格式（写在 prompt 里）依赖模型自觉
- 必须有 **鲁棒解析 + fallback 机制**

📌 **更专业的方案**（未来可选）：
- 用 `response_format={"type": "json_object"}` 强制 JSON 输出
- 用 Pydantic + Instructor 强制 schema
- 加重试机制（解析失败重试 3 次）
- 用 few-shot examples 在 prompt 里给格式示例
