# 20260910 记忆嵌入批量写入：保留 BAAI/bge-m3，减少云端往返

## 一、修改目标

`20260910_smoke5` 显示，开启 `--memory-update` 后单集平均耗时约 44.15 分钟。
当前 `memory.py` 的 `addMemory()` 每收到一条场景就立即调用：

```text
Chroma.add_documents([doc])
  -> SiliconFlowEmbeddings.embed_documents([text])
  -> 一次云端 embedding 请求
```

每集约 500 次 LLM 调用，对应约 500 次 embedding 网络请求，额外耗时约 3.8 秒/次。
本次修改只改变写入方式，不改变 embedding 模型，也不改变记忆检索语义：

- embedding 模型仍为 `BAAI/bge-m3`；
- 仍写入同一个 Chroma 记忆库；
- 仅把逐条网络请求合并为批量请求；
- 默认批大小为 16，可通过 `MEMORY_EMBED_BATCH_SIZE` 调整；
- 设置 `MEMORY_EMBED_BATCH_SIZE=1` 可恢复逐条写入行为。

## 二、修改的原项目文件

1. `llm_controller/memory.py`
2. `Run_multi_CAV_LLM.py`

## 三、具体改动

### 1. `llm_controller/memory.py`

- 新增 `_get_memory_batch_size()`，从环境变量读取批大小。
- 新增常量 `MEMORY_EMBED_BATCH_SIZE`，默认值为 16。
- `DrivingMemory.__init__()` 新增：
  - `self.embed_batch_size`
  - `self._pending_documents`
- `addMemory()` 不再逐条调用 `add_documents([doc])`，而是先缓存 `Document`。
- 当缓冲区达到批大小时，调用新增的 `flush()`。
- `flush()` 将整个文档列表交给 `Chroma.add_documents()`，LangChain 会将其传给 `embed_documents(list)`，从而合并为一次 embedding 请求。
- 批量写入失败时保留缓冲区，不静默清空，后续触发或 episode 结束时重试。
- `retrieveMemory()` 在检索前先执行 `flush()`，保证同时开启写库和检索时，新记忆可见。

### 2. `Run_multi_CAV_LLM.py`

- 每集正常结束后强制调用 `memory.flush()`，保存不足一个 batch 的尾批记忆。
- 单集异常退出时也尝试调用 `memory.flush()`，减少缓存数据丢失。
- `flush()` 内部捕获写入异常，不会因 embedding 失败而掩盖原始 episode 异常。

## 四、不改动的部分

- 不修改主决策模型：仍为 `qwen2.5:32b`。
- 不修改 embedding 模型：仍为 `BAAI/bge-m3`。
- 不修改 prompt、协商逻辑、动作选择、成功判定。
- 不修改 Chroma 的集合名称或记忆库路径。
- 不混合不同 embedding 模型的向量。

## 七、服务器验收标准

运行日志中应出现类似：

```text
Flushed 16 memory items to Chroma.
```

episode 结束时可能出现不足 16 条的尾批：

```text
Flushed N memory items to Chroma.
```

验收条件：

1. 不再出现 `Failed to add scenario batch` 或 401；
2. 每个 episode 结束时尾批被 flush；
3. `Loaded ... Memory` 的条目数大于 0；
4. `progress.json` 包含 2 条有效记录；
5. 单集耗时明显低于原来的约 44 分钟；
6. 成功率、碰撞率等结果用于技术验收，不用于立即推断论文结论。

## 八、回滚方法

无需回滚代码，只需在服务器配置中设置：

```bash
MEMORY_EMBED_BATCH_SIZE=1
```

即可恢复逐条 embedding 请求行为。

## 九、影响说明

- 记忆向量内容理论不变，改变的是请求合并方式。
- 可能需要重新确认 SiliconFlow 对单批输入条数的限制；默认 16 较保守。
- 如果批量请求失败，当前实现会保留缓冲区并重试，不会静默丢弃。
- 本修改尚未提交，需用户确认后再执行 git add/commit/push。
