## 🎯 修改目的

服务器批量实验前的运行器增强，解决 6 个问题：
1. **随机种子不固定**：不同方法看到不同初始场景，对比不公平
2. **视频拖慢实验**：全量每轮都录 mp4 占磁盘和 CPU
3. **记忆库无法构建**：原代码 memory_update 被注释，2shot/5shot 没有种子记忆
4. **成功率口径与论文不一致**：原代码"至少1辆到达"，论文是"所有CAV都到达"
5. **单轮崩溃中断批次**：某轮 LLM 调用超时会导致整个批次中断
6. **输出目录不隔离**：多次实验结果混在一起

### 改动 5：成功判定改论文口径（--strict-success，默认开启）

**原代码（宽松口径）**：
```python
success = (num_crashed == 0) and (num_arrived >= 1)  # 至少1辆到达就算成功
```

**新代码（论文口径，默认）**：
```python
if args.strict_success and scene in ("intersection", "merge"):
    success = (num_crashed == 0) and (num_arrived == num_cav)  # 所有CAV都到达
elif scene in ("intersection", "merge"):
    success = (num_crashed == 0) and (num_arrived >= 1)  # 宽松口径（--no-strict-success）
else:
    success = (num_crashed == 0)  # highway：无碰撞即成功
```

**超时定义**：无碰撞但未全部到达（intersection/merge），单独记录 `timeout` 字段，不和碰撞失败合并。

### 改动 6：单轮错误隔离（try-except）

```python
for i in range(...):
    try:
        # ... 单轮完整逻辑 ...
        records[str(i)] = record
        save_progress(progress_path, records)
    except Exception as e:
        # 单轮崩溃：记录失败，关闭 writer，继续下一轮
        record = {"round": i, "success": False, "error": str(e)[:200], ...}
        records[str(i)] = record
        save_progress(progress_path, records)
        continue
```

某轮 LLM 调用超时、环境崩溃、解析异常等，不会中断整个批次，失败轮次记入 progress.json，后续可用 `--start` 补跑。

## 📚 经验总结

📌 **固定种子是对比实验的基础**：不固定 seed 的话，0shot 成功率低可能只是因为它遇到了更难的初始场景，而不是方法本身差。第 i 轮用 seed+i 是最简单有效的做法。

📌 **视频不需要全量录**：论文里只需要 2-3 个典型场景的视频截图，全量录视频拖慢实验还占磁盘。默认关闭，需要时单独补跑。

📌 **记忆建库要单独跑**：用 0shot（无记忆检索）跑一批轮次写入记忆，然后 2shot/5shot 从同一份库检索。不要在 2shot 实验里边跑边写，会污染检索结果。

📌 **成功率口径必须和论文一致**："至少1辆到达"和"所有车都到达"在 intersection 场景（4-7辆车）下差异巨大，可能差 20-30 个百分点。不改口径的话，你的数据会系统性偏高，没法和论文 Table I 对比。
