# 2026-09-08 修复旧版 gym/highway_env 随机种子兼容问题

## 背景

服务器冒烟测试连续出现三类错误：

1. `reset() got an unexpected keyword argument 'seed'`
2. `'int' object is not callable`
3. `IndentationError: unexpected indent`

## 根因分析

### 1. `reset(seed=...)` 不被支持

`requirements.txt` 固定为 `gym==0.15.3`，本仓库自带 `highway_env` 的环境基类签名为：

```python
def reset(self, is_training=True, testing_seeds=0):
```

因此不能使用新版 Gymnasium 风格的：

```python
env.reset(seed=42)
```

### 2. `env.seed()` 不是可调用方法

`highway_env/envs/common/abstract.py` 中存在两个同名定义：

```python
self.seed = self.config["seed"]  # 实例属性，整数
def seed(self, seeding=None):    # 类方法
```

由于实例属性会遮蔽类方法，运行时 `env.unwrapped.seed` 实际是整数。调用：

```python
env.seed(42)
```

等价于 `42(42)`，因此报：

```text
TypeError: 'int' object is not callable
```

### 3. 手工补丁引入缩进错误

为修复第二个问题而临时加入 `np.random.seed(...)` 时，代码被插入到错误缩进层级，导致：

```text
IndentationError: unexpected indent
```

这类错误不是环境 API 问题，而是热修改代码时未保持控制流层级一致。

## 修复内容

修改 `Run_multi_CAV_LLM.py` 中每轮环境重置逻辑：

```python
obs = env.reset(is_training=False, testing_seeds=args.seed + i)
```

## 为什么这样修复

- 使用本仓库旧版 `highway_env` 明确支持的 `testing_seeds` 参数；
- `is_training=False` 时，环境内部会同时执行：
  - `np.random.seed(testing_seeds)`
  - `random.seed(testing_seeds)`
- 不再调用被整数属性遮蔽的 `env.seed()`；
- 不再需要额外手动设置 NumPy 全局种子；
- 同一 seed 重复 reset 得到相同 observation，满足不同方法对比实验的公平性要求。

## 验证

本地执行最小验证：

```python
o1 = env.reset(is_training=False, testing_seeds=42)
o2 = env.reset(is_training=False, testing_seeds=42)
```

结果：

```text
obs equal: True
```

并执行：

```bash
python -m py_compile Run_multi_CAV_LLM.py
```

检查通过。

## 影响范围

- 仅修改环境 reset 与随机种子设置逻辑；
- 不改变 LLM 调用、记忆库、结果统计和输出目录逻辑。
